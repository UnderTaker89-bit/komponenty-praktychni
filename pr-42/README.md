# Практична робота 42

## Клієнт серверна взаємодія Windows Forms

Предмет Компоненти. Номер у списку 14.

Результат — самодостатнє рішення PostServiceSolution з сервером, бібліотеками моделей, DTO, бізнес логіки, доступу до SQLite та клієнтом PostService.App. Оскільки початковий проєкт ПР-36–41 не надано, сервер реалізовано окремо за контрактом із методички. Правила цієї реалізації наведено в README проєкту; їх не видано за невідомий код попередніх робіт.

### Виконання

1. PostService.slnx містить папки 01-Models, 02-Business, 03-Application Server, 04-Application Client.
2. PostingList є стартовою формою в Application.Run. На ній DataGridView gridPostings і кнопки btnRefresh, btnDelete.
3. Таблиця лише для читання, вибір одного цілого рядка, автоматичні стовпці вимкнені. Створено всі 12 властивостей DTO; Id і CreatedAt приховані.
4. DTO підключено посиланням на спільний проєкт. HttpClient має BaseAddress і тайм-аут, а завантаження виконується через GetFromJsonAsync.
5. LoadPostingsAsync використовується при Load, Оновити та після видалення. Помилки мережі й неуспішні відповіді показуються користувачеві.
6. Видалення бере Id з DataBoundItem, запитує підтвердження, виконує DELETE і перечитує актуальний список.
7. Сервер зберігає дані через ADO.NET та параметризовані SQL запити у postings-ado.db. EF Core додається в окремій ПР-43.

### Запуск і демонстрація

Відкрити PostServiceSolution у VS Code. Виконати dotnet build PostService.slnx; запустити dotnet run --project PostService, потім в іншому терміналі dotnet run --project PostService.App. Приклади POST та GET містяться в http-requests.rest. Є launch.json із compound «Сервер і клієнт» для F5 у VS Code з C# налагоджувачем; PostService.slnLaunch — профіль повної Visual Studio. Форми задані кодом за вимогою користувача, без дизайнера Visual Studio.

Сценарій демонстрації: створити два записи через REST, запустити клієнт, перевірити рядки; створити ще один запис, натиснути Оновити; виділити рядок, Видалити, підтвердити; GET має повернути список без видаленого запису. Зупинити сервер і перевірити повідомлення про помилку.

### Перевірка

Рішення збирається без помилок. Сервер пройшов створення, читання, зміну, перевірку помилкових даних, збереження після перезапуску та видалення. Деталі — Додаткова перевірка.json у корені комплекту. Повний інтерактивний прогін кнопок цієї версії вікна не виконано через технічну недоступність захоплення вікон засобом керування ПК; наведено відтворюваний сценарій для демонстрації.

### Самоконтроль

1. Visual Studio має дизайнер Windows Forms, VS Code не має штатного візуального дизайнера; форми однак можна створювати кодом.
2. Solution folders групують проєкти логічно й не створюють фізичні каталоги.
3. Стартову форму визначає аргумент Application.Run.
4. Посилання на DTO запобігає розходженню контрактів. Клієнт іншою мовою потребував би власного опису JSON контракту.
5. HttpClient виконує HTTP запити; BaseAddress задає основу відносних адрес.
6. Await звільняє потік інтерфейсу під час мережевого очікування.
7. Async void допускається для обробників подій, Task повертається звичайними методами, щоб їх можна було очікувати й контролювати винятки.
8. CurrentRow.DataBoundItem перетворюється на PostingGetDto; Id включається в DELETE /postings/{id}.
9. Повторне читання враховує фактичний стан сервера та зміни інших клієнтів.
10. Спільний метод усуває дублювання завантаження та обробки помилок.
